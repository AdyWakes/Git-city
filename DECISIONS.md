# Decisions log

Choices made autonomously while building, with the reasoning, so they can be revisited.

1. **Name: `gitcity`.** Checked npm on 2026-11-05: `gitcity`, `git-city` were both unpublished (`repocity` and `commitcity` are taken). `gitcity` matches the working name and the repo, so it stays. Nothing was published.
2. **Zero runtime dependencies for the CLI.** Arg parsing, the static server and browser opening are hand-written on Node built-ins so `npx gitcity` installs in a second. Three.js and Vite are dev dependencies; the viewer is pre-bundled into `dist/viewer`.
3. **Typecheck instead of ESLint** in CI to keep the toolchain small (`tsc --noEmit` on both the CLI and viewer projects). ESLint is listed as a good first issue.
4. **`git log -z --raw --numstat -M --reverse`** instead of plain `--numstat`. `-z` makes paths verbatim (no C-quoting, safe for spaces/unicode/`=>`), `--raw` gives an explicit status letter so deletions are unambiguous (numstat alone cannot tell "file deleted" from "file emptied"), `-M` follows renames so a moved file keeps its building. Merge commits produce no diff by default, so lines are counted exactly once, in the commit that introduced them.
5. **Mapping scales.** Footprint = commits on a log10 scale (1-9 commits = 1 cell, 10-99 = 2, 100-999 = 3, 1000+ = 4) so a hot file is visibly wider without one file eating a district. Height = lines on a square-root scale in the viewer (linear made one generated file dwarf everything). Both are documented in the README.
6. **Layout: downtown spiral.** Inside a district the heaviest files are placed first on a square spiral from the center (every 6th row/column is a street), so each district has a skyline core. Districts are placed largest-first on a circular spiral. Ties break on path so the layout is fully deterministic.
7. **Smart districts.** "Top-level folder = district" makes `src/` or `packages/` one giant blob in many repos. If a folder holds more than half of the rendered buildings and has 2+ sub-folders, it is split into its sub-folders (up to 3 levels). Root-level files form a `(root)` district.
8. **Time-lapse ticks.** History is bucketed into at most 1200 ticks of consecutive commits (by commit index, not calendar time), so quiet years don't stall the replay and the event list stays bounded: one event per (tick, file).
9. **Deleted files.** The largest deleted files (by peak size) become dark lots, capped at 12% of the building cap and at half the number of live buildings, so old history doesn't turn a small repo into a parking lot. Binary files are not rendered (their "lines" are meaningless).
10. **One InstancedMesh, LOD in the shader.** All buildings and lots share one InstancedMesh (one draw call; 20k boxes are only 240k triangles). Level of detail is done on the GPU: windows are analytic and fade to their average glow once they are smaller than a couple of pixels, and buildings smaller than ~1.5px collapse in the vertex shader. Per-chunk frustum culling was skipped: draw-call count matters more than vertex count on integrated GPUs.
11. **Adaptive quality.** The viewer measures the median frame time; above 21ms it drops to "medium" (pixel ratio 1), then "low" (no bloom, pixel ratio 0.75). Bloom always runs at half resolution.
12. **Visual identity.** Night palette with warm sodium windows (and ~18% cool white ones), a dusty violet horizon, neon crowns only on the top ~2.5% tallest towers, and a single UI accent (`#ff4f8b`) that is also the hover/search highlight. Monospace wordmark, large repo name, no cards or panels except the floating search/tooltip.
13. **Scrubber shows the growth curve, not commit counts.** Ticks are equal-sized commit buckets, so a commits-per-tick histogram would be flat. The scrubber instead draws total lines of code over time (the city's skyline growth) with year marks.
14. **Contributor lights** are pooled (72 slots, least-recently-active reused) with short trails; they fly in from the horizon at an angle derived from the author id, hover over each building the author changes, and fade after ~3s idle. Cool white-blue so they read against amber windows.
15. **Export composition.** Exports render the WebGL scene at the exact output size, then composite in a 2D canvas: repo title + stats top-left, the current date during time-lapses, district names, and a small `■ gitcity  owner/repo` watermark bottom-right. Portrait exports pull the camera back by (aspect ratio)^0.45, cropping into the skyline instead of shrinking the city.
16. **Video timing.** MediaRecorder records in real time, so the time-lapse is driven by wall-clock time (exactly 10s; the last 1.2s holds on the finished city). If three 1080p test frames average >40ms the recording falls back to 1280x720 so slow GPUs still produce a smooth video.
17. **Bare clone.** Remote repos are cloned with `git clone --bare --progress` into `os.tmpdir()/gitcity-*`. It is a full clone of the history (as requested) but skips the working-tree checkout, which `git log` doesn't need. The temp folder is deleted as soon as the city is built (the server only needs the JSON in memory), and on SIGINT/exit; `--keep` retains it. `GIT_TERMINAL_PROMPT=0` makes private/missing repos fail fast instead of hanging on a password prompt.
18. **`owner/repo` shorthand** is treated as GitHub only when no local folder with that relative path exists.
